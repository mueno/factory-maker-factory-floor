# Factory Maker UXリニューアル実装監査

監査日: 2026年9月3日
対象: リニューアル後のFactory Maker本体、生成サービス、日英表示、法務ページ、依存関係

## 結論

公開を止める重大・高重要度の未対応事項はありません。既存依存関係から検出した高重要度の脆弱性は、安全版への更新後に再監査し、本番・開発依存関係ともに0件となりました。

## 確認結果

| 観点 | 結果 | 確認内容 |
| --- | --- | --- |
| WebMCP | 合格 | 工程と画面に応じてツールが入れ替わり、読取・変更を区別。ブラウザ上で登録を確認 |
| 人の決定権 | 合格 | 企画要旨の承認、方向選択、仕様固定、試行承認をWebMCPツールから除外 |
| 状態整合性 | 合格 | 変更系ツールに版番号を要求し、古い版への書き込みを状態変更なしで拒否 |
| 回復 | 合格 | AIの直前操作を、履歴を消さずに新しい版として打ち消す経路を用意 |
| データ最小化 | 合格 | 作業状態と表示言語はブラウザ内保存。アプリ用DB、ログイン、広告、アクセス解析なし |
| 入力安全性 | 合格 | 個人・機密・健康・決済情報を入力しないよう、入力欄、フッター、規約で表示 |

| アクセシビリティ | 合格（範囲限定） | ラベル、見出し、フォーカス表示、44px前後の主要操作、色以外の状態表示、縮小動作抑制を確認。WCAG適合認証ではない |
| モバイル | 合格 | 390×844で、工程、現在の成果物、AI操作を縦の流れに再構成 |
| 法務表示 | 合格（試作範囲） | 日本法、責任制限の例外、第三者サービス、保存・削除、言語優先、公式規則へのリンクを記載。個別案件への法律意見ではない |
| 依存関係 | 合格 | `npm audit` 0件、`npm run lint` 合格、`npm run build` 合格 |

## 実ブラウザで完走した流れ

1. 架空の依頼を企画要旨へ整理
2. 人が内容を承認
3. AIが3つの方向案を作成
4. 人が一案を選択
5. AIが構築仕様案を作成
6. 人が仕様を固定
7. AIが動く意思決定ボードを生成
8. 候補を採点し、人が試行を承認
9. 元の画面へ戻り、5項目の検証を実行
10. すべての検証結果を、版番号と出力ハッシュに結び付けて表示

ブラウザの開発者ログには、警告・エラーともに記録されませんでした。

## ハッカソン応募時の境界

- 一般公開URLから、登録やログインなしで利用できる状態を維持する。
- 審査用のデータは架空データと明示し、実在する顧客案件や個人情報を入力しない。
- 動画では、通常のクリック自動化ではなく、ページ自身が公開するWebMCPツールと同じ画面状態の更新を示す。
- 検証への合格を、本番運用の準備完了、法令適合または第三者認証として説明しない。
- 応募条件は[WebMCP Challenge公式規則](https://webmcp.devpost.com/rules)を正本とする。
