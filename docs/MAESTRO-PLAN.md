## 2. 注目の法則（言語化）

1. **エージェントが主役の逆転構図** — 「AIがフォームを埋めてくれる」(道具)より「AIが演じる・戦う・脱出する」(主役)が語られる。Maze/Blackjackが証拠。
2. **サムネイル一文の法則** — 「プロンプトだけで迷路脱出」のように、**10秒・一文・一画面**で伝わる前提を持つものだけが拡散する。
3. **『初めて見た』が『便利』に勝つ** — 効率化の実演（予約が速い）は感心止まり。**標準がなければ存在しえなかった相互作用**が言及を生む。
4. **画は動いてなんぼ** — 3分動画が提出様式。静的UIのスクリーン録画は差がつかない。**動き・光・変化量**が視聴維持率を作る。
5. **ツール契約の美しさは二次拡散を生む** — 開発者はコードを読む。少数の型付きツールでdescription駆動する設計はDevRel（Chrome/OpenAI）が引用しやすい。
6. **その場で触れること** — ライブURL + OSS + 1行で試せる導線。触った人がクリップを作る。

### 割り勘スタジオの敗因（この法則で採点）

主役=人間のフォーム(1✗)、一文で驚けない(2✗)、Excelで可能(3✗)、画が静的(4✗)。ツール契約(5)だけが良かった。**土台は正しく、演目が間違っていた。**

## 3. 企画: MAESTRO（マエストロ）

> **「操作しない。指揮する。」— ブラウザのAIエージェントが、百万粒子の世界をライブで演奏するWebMCPステージ。**

### 体験

1. 画面全体が、端末GPUで動く粒子×流体の世界（パターンB・全処理オンデバイス）
2. 人間は**触れる**: ポインタは風、クリックは脈動（現行世界レイヤーの拡張）
3. エージェントは**指揮する**: WebMCPで公開された「楽器」ツールを呼び、嵐を呼び、オーロラを張り、**百万の粒子で文字や図形を描かせる**
4. 「桜吹雪にして、最後に 'WebMCP' って書いて」→ エージェントが `set_weather` → `conjure_text` を編成 → 粒子が収束して文字になる（**これがサムネイルの一枚**）

### なぜ勝てるか（法則との対応）

| 法則 | MAESTROの回答 |
|---|---|
| 1 主役の逆転 | エージェント=指揮者。ツール呼び出し1つごとに世界が劇的に変わる |
| 2 一文 | 「AIエージェントに、百万の粒子を指揮させた」 |
| 3 初めて見た | エージェント×リアルタイムGPU世界の組み合わせは掲載事例ゼロ |
| 4 画force | 全編が光と動き。録画するだけで映える |
| 5 契約美 | 楽器メタファーの型付きツール8個・description駆動 |
| 6 触れる | Codex Siteの静的配信で誰でも即体験（GPUはユーザー端末） |

### WebMCP楽器（Tool Contract）

| ツール | 入力 | 効果 |
|---|---|---|
| `stage_read` | — | 現在の天候・パレット・粒子数・直近の人間シグナル（読取専用） |
| `stage_weather` | preset: calm/storm/aurora/sakura/ember | 風場・乱流・重力・パレットの一括演出 |
| `stage_conjure_text` | text(≤12), hold_sec | **粒子が収束して文字を描く**（撒布→収束→保持→解放） |
| `stage_conjure_shape` | shape: heart/star/spiral/ring/wave | 図形整列 |
| `stage_palette` | tone: cyan/gold/coral/violet/mono | 染料・粒子色 |
| `stage_pulse` | x, y, power | その座標に光の脈動 |
| `stage_gravity` | direction: up/down/center/none | 重力操作（粒子が落ちる/舞い上がる） |
| `stage_scatter` | — | 全解放（リセット演出） |

- 全ツール、引数はenum/短文/数値のみ（サニタイズ簡明・インジェクション面が構造的に小さい）
- 同じ契約を台本Brain（デモ用シーケンス再生）とDirect APIが共有 — Adlibの「単一契約・複数頭脳」を継承
- 人間UIにも同じ楽器のボタン列を置く（**エージェントなしでも成立**、エージェントで完全体）

### パターンB技術設計（world.ts拡張）

```
既存: 流体場（速度・染料・渦度・圧力射影）= 「風と光」
追加: 粒子系（20万〜100万、端末性能で自動段階調整）
  - update kernel: 粒子は流体速度場に運ばれる + ターゲット引力 + 重力
  - ターゲット: 文字/図形をオフスクリーンcanvasにラスタライズ → 
    輝点座標をサンプリングしてstorage bufferへ → 粒子ごとの目標点
  - render: additive blendingの点描画（glow）
既存資産の再利用率: 世界レイヤー約7割・ツール層/Brain/Stage骨格はそのまま
```

- 文字整形 = 「構造化ツールへの正確な入力→物理世界の精密な出力」の証明であり、単なる飾りではなくWebMCPの価値実証
- フォールバック: WebGPU非対応→静的スキン+ツールは動画/説明モードで応答（現行方式踏襲）

### 3分動画 絵コンテ

| 時間 | 画 | ナレーション（要旨） |
|---|---|---|
| 0:00-0:15 | 暗転→ポインタ一閃で粒子が渦巻く | 「これはUIではありません。世界です」 |
| 0:15-0:45 | エージェントのチャットとステージの分割画面。「嵐にして」→ `stage_weather{storm}` 呼び出しログ→世界が荒れる | 「このページはWebMCPで楽器を公開しています。演奏者は、あなたのブラウザのAIです」 |
| 0:45-1:30 | 連続指揮:「桜吹雪→ハート→ 'WebMCP' と書いて」→ 粒子収束の3連発 | ツール契約を1画面で見せる（8楽器） |
| 1:30-2:10 | 人間の手（ポインタ）とエージェントの指揮が同じ世界に共存 | 「人は触れ、エージェントは指揮する。同じ物理、同じ契約」 |
| 2:10-2:40 | コード: registerTool 8個・description・enum引数。Codex Site静的配信+全GPU処理オンデバイスの図 | 「サーバーにGPUはありません。全てあなたの端末で」 |
| 2:40-3:00 | `stage_conjure_text{"MAESTRO"}` → タイトルが粒子で組み上がって終幕 | ロゴ+URL |

### 実装計画（締切 9/4 逆算・Adlib資産上に構築）

| # | 作業 | 目安 |
|---|---|---|
| 1 | world.ts拡張: 粒子バッファ+update/render kernel（流体場サンプル+目標引力） | 3h |
| 2 | テキスト/図形ラスタライズ→ターゲット供給（CPU側、Canvas2D） | 1.5h |
| 3 | 天候プリセット・パレット・重力のパラメータ演出 | 1h |
| 4 | WebMCP楽器8ツール登録（Adlib tools.ts置換）+人間用楽器ボタン列 | 1.5h |
| 5 | 台本Brain=デモ演目シーケンス、ヒーローUI（MAESTROブランド・最小コピー） | 1.5h |
| 6 | 検証（Playwright+実機）、README（OSS要件）、動画素材撮り | 2h |

計 ~10.5h。割り勘スタジオ由来のフォーム改変UIは非表示化（コードは残置可）。

### リスク

| リスク | 対策 |
|---|---|
| 締切まで<24h | 楽器を8→5に減らしても成立（weather/text/palette/pulse/scatter が最小完全体） |
| 低スペック端末 | 粒子数の自動段階（20万→5万）+流体解像度は現行のまま |
| 審査環境にWebMCPエージェントが無い | 人間用楽器ボタン+台本演目で全機能が単独実演可能。動画はChrome 149+Gemini実写 |
| 文字整形の品質 | 12文字上限・太字フォント・収束時間1.5sで安定側に振る |
